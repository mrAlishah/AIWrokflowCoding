# هدف

گردش‌کار PBI را با skill `pbi_clarification` به‌شکل امن شروع می‌کند.

این prompt یک launcher است. کل workflow PBI را در یک اجرا انجام نمی‌دهد؛ فقط workflow را شروع می‌کند و اگر PBI آماده باشد، prompt مرحله بعدی را آماده می‌کند.

# پارامترها

| پارامتر | ضروری | توضیح |
|---|---|---|
| STP_ID | اختیاری | شناسه PBI هدف وقتی مشخص است. مثال: STP-123. |
| RAW_PBI | بله | متن خام PBI، user story، feature request یا requirement اولیه. |
| REQUESTER | اختیاری | نام درخواست‌دهنده. مثال: Mostafa. |

# گزینه‌های پارامترها

## STP_ID

| گزینه | توضیح |
|---|---|
| گزینه ثابت ندارد | از شناسه پایدار مثل `STP-123` استفاده کن، یا اگر skill اجازه می‌دهد آن را قابل استخراج بگذار. |

## RAW_PBI

| گزینه | توضیح |
|---|---|
| متن آزاد | متن خام PBI یا user story را وارد کن. |

## REQUESTER

| گزینه | توضیح |
|---|---|
| متن آزاد | فرد درخواست‌دهنده کار. |

# ورودی‌های لازم

- PBI خام یا user story
- شناسه اختیاری STP

# خروجی‌های مورد انتظار

- PBI شفاف‌شده یا سوال‌های clarification
- prompt آماده مرحله بعد برای `pbi_workspace_create` وقتی PBI آماده باشد

# قوانین

| قانون | توضیح |
|---|---|
| یک skill | در این اجرا فقط `pbi_clarification` اجرا شود. |
| بدون تغییر source code | تغییر source code ممنوع است. |
| بدون زنجیره‌سازی خودکار | prompt مرحله بعد را آماده کن، ولی اجرا نکن. |
| context محدود | فقط skill انتخاب‌شده و context لازم را بخوان. |

# خطاهای رایج

- درخواست اجرای کل PBI workflow در یک prompt.
- رد شدن از clarification برای PBI مبهم.
- ساخت workspace قبل از آماده بودن PBI.

# نکته‌های بهینه‌سازی context

- RAW_PBI را کوتاه و دقیق نگه دار.
- جزئیات طولانی را فقط وقتی اضافه کن که روی acceptance criteria اثر دارد.
- در هر درخواست فقط یک PBI skill اجرا کن.
