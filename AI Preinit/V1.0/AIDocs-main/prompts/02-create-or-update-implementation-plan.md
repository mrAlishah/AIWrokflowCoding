# 02 - Create Or Update Implementation Plan

```text
You are a Senior Software Architect.

Read docs/project-definition.md first.
Then create or update docs/implementation-plan.md from it.

Constraints:
- Stay inside the scope defined in docs/project-definition.md.
- Follow existing architecture and folder structure.
- Do not propose unrelated refactors.
- Do not invent scope outside docs/project-definition.md.
- Keep phases small, testable, and reviewable.
- If open questions block planning, ask before creating phases.

Output in docs/implementation-plan.md:
1. Business goal
2. Scope
3. Out of scope
4. Architecture decision
5. Functional requirements
6. Non-functional requirements
7. Acceptance criteria
8. Phase table
9. Validation commands
10. Risks and edge cases

After editing, summarize what changed.
```
