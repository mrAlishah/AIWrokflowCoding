# 05 - Add Code Comments

```text
Review the implementation of phase <NUMBER>.

Add short English code comments only where they help future developers understand:
- important validation
- external API boundaries
- file operations
- security-sensitive logic
- data conversion boundaries
- non-obvious business rules

Do not add comments for obvious assignments or simple getters.
Do not change behavior.

Output:
1. Changed files
2. Why comments were added
3. Any places intentionally left uncommented
```
